# 03 · CAN 双板主从通信 · 开发文档

对应《G308 电控组 2026 年夏季考核题》软件部分第三题。
硬件：STM32F103C8T6 ×2 + TJA1050 收发器 ×2。
仓库：[github.com/mydsp/can-exam](https://github.com/mydsp/can-exam)

## 1. 项目概述

两块开发板组成 CAN 总线主从系统：主机检测按键按下后发送数据 `0x11` 并把收到的数据
打印到串口助手；从机收到 `0x11` 后回传 `0x22` 并翻转板载 LED。

| 题面要求 | 实现 |
| --- | --- |
| （1）模块化思路，创建一对 `can.c`/`can.h` 通用通信函数 | 驱动与应用完全解耦，见 §4 |
| （2）两块板主从，主机按键发 `0x11`，从机回传 | 主机 PB0 边沿检测 → 发 `0x11`；从机回 `0x22` |
| （3）主机收到数据打印到串口助手 | `RX ID=0x022 DLC=1 DATA=0x22` |
| （4）从机接 LED，每收到一次翻转亮灭 | PC13 翻转 |
| 提交：项目文件 / 开发文档 / 实操视频 | 本仓库 / 本文 / `docs/video/soft3-demo.mp4` |

## 2. 平台选型

本题初期曾计划沿用前两题的 STM32F401RET6，编写时确认 F401 产品线不含 bxCAN 控制器
（CMSIS 头文件 `stm32f401xe.h` 中无任何 CAN 定义），而 TJA1050 只是物理层收发器，
缺少控制器无法工作。因此正式方案采用 **STM32F103C8T6** 双板，它带原生 bxCAN。

## 3. 硬件与接线

| C8T6 引脚 | 连接 | 说明 |
| --- | --- | --- |
| PA12（CAN_TX） | TJA1050 TXD | 3.3V 直连（TXD 阈值约 2V） |
| PA11（CAN_RX） | TJA1050 RXD | **经 1kΩ 串联 + 2kΩ 下拉分压** |
| 5V / GND | TJA1050 VCC / GND | 模块必须 5V 供电 |
| PC13 | 板载 LED | 低电平点亮 |
| PB0 | 按键 → GND | 内部上拉，低有效 |
| 总线 | CANH↔CANH、CANL↔CANL | 总线两端各保留一个 120Ω 终端电阻 |

两条电平与总线规则：

- **TJA1050 为 5V 芯片，RXD 输出高电平约 5V**，直接接入非 5V 容忍引脚会超规格。
  1k/2k 分压后约 3.3V，符合 C8T6 输入要求。跨电压域信号的原则是：
  MCU 发往 5V 器件可直连，5V 器件发往 MCU 必须处理。
- **CANH 与 CANL 不可用导线直接短接**，否则收发器差分输出互相对冲，有过流风险。
  测量端接电阻时用万用表量 CANH-CANL（双板各 120Ω 并联约 60Ω）。

## 4. `can.c` / `can.h` 模块设计

接口不含任何业务语义，文件头注明约束：**更换应用场景时只改 main，不动 can.c**。

```c
typedef enum {
  CAN_WORK_NORMAL   = 0,   /* 正常收发 */
  CAN_WORK_LOOPBACK = 1    /* 回环自测，无外部节点亦可验证 */
} can_work_mode_t;

typedef struct {
  uint32_t id;             /* 标准帧 / 扩展帧 ID，内部按 IDE 自动区分 */
  uint8_t  data[8];
  uint8_t  len;            /* 0~8 */
} can_frame_t;

void CAN_Init(can_work_mode_t mode);
bool CAN_Send(uint32_t id, const uint8_t *data, uint8_t len);
bool CAN_Recv(can_frame_t *f, uint32_t timeout_ms);
void CAN_FlushRx(void);
```

设计要点：

- 枚举命名为 `CAN_WORK_*` 而非 `CAN_MODE_*`，避免与 HAL 宏重名。
- `CAN_Send` 不阻塞：邮箱满立即返回 `false`，重试策略交由应用层决定。
- 接收过滤器配置为全接收（Mask 全 0，FIFO0）。bxCAN 不配置过滤器将收不到任何帧。
- `CAN_Recv` 同时兼容标准帧与扩展帧，DLC>8 时截断到 8。

## 5. 主从角色与工程组织

同一份 `can.c`/`can.h`，两个角色由 CMake 预设切换：

| 预设 | 宏 | 产物 | 行为 |
| --- | --- | --- | --- |
| `master` | `CAN_ROLE_MASTER=1` | `build/master/can-master.bin` | 按键 → 发 `0x11` → 5ms 超时收应答并打印 |
| `slave` | `CAN_ROLE_SLAVE=1` | `build/slave/can-slave.bin` | 50ms 超时收 `0x11` → 翻转 PC13 → 回 `0x22` |

报文约定：`CAN_ID_CMD = 0x11`、`CAN_ID_ACK = 0x22`，标准帧，DLC=1，数据与 ID 同值。

## 6. 位时序

目标 500 kbit/s：

```
HSE 8MHz × PLL9 = 72MHz SYSCLK，APB1 = 36MHz
Prescaler = 9 → tq = 4MHz
BS1 = 5 tq，BS2 = 2 tq，SJW = 1 tq → 每位 8 tq
波特率 = 4MHz / 8 = 500 kbit/s，采样点 = 75%
```

时钟树显式配置：HSE 8MHz、PLL×9、SYSCLK 72MHz、APB1 36MHz、APB2 72MHz。
CAN 位时序与串口波特率均由时钟分频决定，因此时钟配置必须显式完成并核对。

## 7. 构建与烧录

```powershell
cmake --preset master ; cmake --build --preset master   # 主机
cmake --preset slave  ; cmake --build --preset slave    # 从机
pyocd flash -t stm32f103c8 build\master\can-master.bin
pyocd flash -t stm32f103c8 build\slave\can-slave.bin
```

## 8. 验收步骤

| 步骤 | 预期现象 |
| --- | --- |
| 上电 | 两板串口各打印一行 `role=master` / `role=slave` |
| 按一次主机 PB0 | 主机打印 `TX ID=0x11 DATA=0x11`，随后 `RX ID=0x022 DLC=1 DATA=0x22` |
| 从机串口 | `RX ID=0x011 DLC=1 -> toggle LED, reply 0x22` |
| 从机板 | PC13 翻转一次 |
| 连续按键 | 三个环节一一对应 |

## 9. 总线联调前的链路预验证

双 F103 联调之前，用两块 ESP32-S3 + 同样的 TJA1050 预先验证了收发器链路
（`esp32-selftest/`，含单节点自发自收与双节点互发两种模式）。
目的是**切分故障域**：若直接双 F103 不通，难以区分"控制器配置错误"与"收发器/接线错误"。
预验收通过后，双板联调阶段的问题即可聚焦在配置层面。
ESP32 方案仅用于链路预验证，不能替代双 F103 的正式验收。

## 10. 已知限制

- 协议为单帧请求-应答，无多帧分包、序号与超时重传（题面未要求）。
- 波特率固定 500 kbit/s。
- 从机按 ID 判定后即应答，未校验载荷内容；若扩展为带参数命令，在 `main.c` 加判定即可，驱动层无需改动。

## 11. 调试记录

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 主机持续 `TX failed (mailbox busy)`，串口波特率也不对 | 时钟树未显式配置，CAN 位时序与串口分频同时偏移 | 显式配置 HSE/PLL/APB 分频（见 §6） |
| 通信看似正常，RX 引脚异常、芯片发热 | TJA1050 RXD 的 5V 直灌 PA11 | 1kΩ + 2kΩ 分压后接入 |
| 发送成功但对端无反应 | 终端电阻缺失 / CANH-CANL 接反 / 单节点无 ACK | 按电阻→线序→供电→引脚顺序排查 |
| 旧工程 `can.c` 在 F401 上编译失败 | F401 无 bxCAN 控制器 | 更换 C8T6 平台（见 §2） |
